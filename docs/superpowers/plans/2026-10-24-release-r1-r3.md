# SMOKESTACK 1.0 R1–R3: Pages, Design System, Clarity Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the game as a static GitHub Pages site and replace the improvised interface with
one designed system ("Brass & Ledger"). Add an alerts tray, map status badges and a production
codex, so problems and chains are visible at a glance.

**Architecture:**
- **R1:** static build with `base: './'` and a Pages workflow.
- **R2:**
  - design tokens in `src/ui/theme.css`, with the old variable names kept as aliases;
  - a small DOM component kit (`src/ui/kit.ts` + `src/ui/kit.css`) built on the existing `h()`
    helper;
  - every screen reworked onto the kit.
- **R3:** a read-only game-layer alerts model, a top-bar tray, badges drawn in the render overlay
  pass, and a codex panel registered in `PANELS`.

**Tech Stack:** TypeScript 5.6 strict, DOM + CSS, Canvas 2D, Vite 5, Vitest + jsdom, and
`@fontsource/playfair-display` 5.x and `@fontsource/source-sans-3` 5.x as devDependencies
(they ship as woff2 assets).

**Spec:** `docs/superpowers/specs/2026-10-24-smokestack-1.0-release-design.md` (§4 R1, §5 R2, §6 R3).

## Global Constraints

- **Code boundaries:**
  - `src/sim` is not modified, except where Task 14 reads from it. All new logic is in `src/game`,
    `src/ui` and `src/render`.
  - No runtime JS dependencies and no CDN calls at runtime. Fonts are bundled with `@font-face`
    through the `@fontsource` CSS imports, latin subset, weights 400/700 (Playfair 700 only).
- **Assets:** no emoji in `src`. Icons come from the atlas (`src/ui/icon.ts` `iconEl`).
- **Type scale, exactly:** `--fs-xs: 11px`, `--fs-sm: 12.5px`, `--fs-md: 14px`, `--fs-lg: 18px`,
  `--fs-xl: 26px`.
  - Uppercase letter-spaced text (0.08em) is used only for overlines at `--fs-xs`.
- **Space:** 4, 8, 12, 16, 24, 32 px as `--sp-1` … `--sp-6`. Radius: `--r-sm: 3px`, `--r-md: 6px`.
- **Keep these class names** on the reworked elements, because tests and the tutorial use them:
  `.window`, `.window-title`, `.window-body`, `.window-close`, `.hud-panel-btn[data-panel]`,
  `.tb-tab[data-tab]`, `.tool-card[data-building]` and `.btn`.
  - When a task changes a test selector, it says so.
- **Layout bounds:** must work at 1366×768 and 1920×1080. At 1366×768 with one panel open, at
  least 60% of the width is map.
- **Accessibility:**
  - Icon-only buttons keep `aria-label` and a `title` that includes the shortcut.
  - Text tokens meet WCAG AA (4.5:1) on their surfaces.
- **Dev-only debug parameters** stay dev-only (`import.meta.env.DEV`).
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work is on the
  `release/r1-r3` branch.

## Review Focus

1. **Empty and early-game states.** A fresh 1900 game has no ledger history, routes, managers or
   alerts. Every reworked panel must show a designed empty state, never a blank area or a chart
   frame with one point. Pinned in Tasks 6–9 by an "empty game" test per panel.
2. **Long names and big numbers.**
   - A 32-character company name and a $1,234,567,890 balance must not wrap or overflow the top
     bar at 1366 px. They are truncated with an ellipsis and a full `title`.
   - Long town and building names in tables are truncated the same way.

   Pinned in Task 4 and Task 3 (`dataTable`).
3. **Alerts that point at things that no longer exist.** A building that was demolished, or a
   vehicle that was sold, while its alert is in the tray must not throw when clicked. The tray
   re-collects the alerts and drops the item. Pinned in Task 13.
4. **UI scale.** At 80% and 130% scale the new top bar and the tray must stay on one row or
   within the viewport, and map clicks must still land on the tile under the cursor. Pinned in
   Task 4 and Task 13 with a scale test.
5. **Pages subpath.** The built `dist/index.html` must not reference any absolute `/` asset path,
   including the font files, so the site works at `https://<user>.github.io/<repo>/`. Pinned in
   Task 1 (`scripts/check-dist.mjs`) and rerun in Task 16.

### Task 3: Component kit

**Files:**
- Create: `src/ui/kit.ts`, `src/ui/kit.css`, `src/ui/kit.test.ts`

**Interfaces:**
- Consumes: `h` from `src/ui/dom.ts`, `iconEl` and `IconId` from `src/ui/icon.ts`, and the
  tokens from Task 2.
- Produces (all return `HTMLElement`):
  - `type Tone = 'neutral' | 'positive' | 'negative' | 'warning' | 'info'`
  - `button(label: string, opts: { variant?: 'primary' | 'secondary' | 'quiet' | 'danger'; icon?: IconId; shortcut?: string; onClick?: () => void; disabled?: boolean; title?: string })`.
    The default variant is `'secondary'`. The class is `btn kit-btn kit-btn--<variant>`. A
    shortcut renders as `<kbd>` and is appended to `title` as ` (X)`.
  - `panelHeader(o: { title: string; summary?: string; tone?: Tone; icon?: IconId })`. It has the
    class `kit-ph`; the summary carries `kit-ph-summary` and `data-tone`.
  - `statTile(o: { label: string; value: string; delta?: string; tone?: Tone; title?: string })`
    and `statRow(tiles: HTMLElement[])`. A tile has the class `kit-stat`, and `.kit-stat-value`
    uses `--font-display`.
  - `pill(text: string, tone: Tone = 'neutral', icon?: IconId)` (the class is `kit-pill kit-pill--<tone>`).
  - `meter(value: number, max: number, o?: { tone?: Tone; label?: string })`. It sets
    `role="meter"`, `aria-valuenow`, `aria-valuemax` and clamps to [0, max]. A NaN value renders
    as empty.
  - `dataTable<T>(o: { columns: { key: string; label: string; align?: 'left' | 'right'; render: (row: T) => Child; title?: (row: T) => string }[]; rows: T[]; emptyText: string; rowKey?: (row: T) => string; onRowClick?: (row: T) => void })`.
    Numeric columns are right-aligned. Cells have `title` when `title` is given and are
    truncated with an ellipsis by CSS. An empty `rows` renders `emptyText` in a `.kit-empty-row`.
  - `emptyState(o: { icon?: IconId; title: string; body?: string; action?: HTMLElement })` (the
    class is `kit-empty`).
  - `card(o: { title?: string; children: Child[]; actions?: HTMLElement[]; tone?: Tone })` (the
    class is `kit-card`).
  - `section(title: string, children: Child[], o?: { collapsible?: boolean; open?: boolean; id?: string })`.
    It renders a `<details>` when collapsible, otherwise a `<section class="p-section kit-section">`
    whose heading `h3.p-head` is an overline.
  - `tooltip(target: HTMLElement, content: () => HTMLElement | string)`:
    - one shared `.kit-tip` element, shown on `pointerenter` and on focus, after a 250 ms delay;
    - hidden on leave, on blur and on Esc;
    - positioned inside the viewport (flipping above or below);
    - returns a disposer.
  - `deltaText(v: number): string`: `"▲ $4,077"` for a gain, `"▼ $12,000"` for a loss and
    `"$0"` for zero, using `formatMoney` with the sign removed.
- **Styling:**
  - `kit.css` uses only tokens.
  - Primary is filled `--accent` with `--paper-ink` text; secondary is outlined with
    `--accent-quiet`; quiet is text only; danger is outlined with `--negative`.
  - Every interactive element has a `:focus-visible` style using `--focus`.
  - Add `src/ui/kit.css` to `MIGRATED_CSS`.

### Task 12: Alerts model

**Files:**
- Create: `src/game/alerts.ts`, `src/game/alerts.test.ts`

**Interfaces:**
- Produces:
```ts
export type AlertTone = 'warning' | 'negative' | 'info';
export type AlertTarget =
  | { kind: 'building'; id: number }
  | { kind: 'vehicle'; id: number }
  | { kind: 'panel'; panel: string };
export interface Alert { id: string; tone: AlertTone; icon: IconId; title: string; detail: string; target: AlertTarget }
export class AlertTracker {
  /** first day (dateToDays) each condition id was seen; ids not seen this call are forgotten */
  collect(state: GameState): Alert[];
}
```
- **Rules.** All are for the player's own things only. Ids are stable strings, e.g.
  `b:<id>:no_input`.

  | Condition | Tone | Title |
  |---|---|---|
  | Building `no_input` for 7+ days | warning | "<Building> is starved" |
  | Building `output_full` for 7+ days | warning | "<Building> is backed up" |
  | Building on strike (`halted` with a strike) | negative | "Strike at <Building>" |
  | Building `idle` for 7+ days | info | "<Building> is idle" |
  | Vehicle idle for 14+ days | info | "<Vehicle model> idle" |

  Other alerts:
  - The last closed ledger month had a loss: `panel: 'finance'`, negative, "Last month lost $X".
  - A pending event card: `panel: 'newspaper'`, or whatever panel the game uses for cards.
    Tone info, title "A decision awaits".
  - A Baron move this month: `panel: 'rival'`, negative.
  - An active mayor's contract due within 30 days and not yet fulfilled: `panel: 'contracts'`,
    warning, "Contract for <town> due in N days".

  The detail line for each building alert is `statusAdvice(...).text` from Task 8.
- **Order:** negative first, then warning, then info; within a tone, oldest first. A maximum of
  50.
- **Purity:** read-only. No rng, and nothing is written to `state`.
